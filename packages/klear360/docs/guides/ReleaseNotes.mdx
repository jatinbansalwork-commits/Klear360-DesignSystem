# Release notes

What changed, and why it mattered. These are the project's own words for itself — not the
changelog engineers read, the one everyone else does. You're on <Badge color="primary">v0.5.3</Badge>.

<br />
<br />

## v0.5.3 · Wed, Oct 21

Today was a tidy-up day, and it turned up more than expected. We checked every loading spinner,
every "nothing here yet" moment, and every animation timer in the kit against each other, the way
you'd check that every door in a house closes the same way. Most of it held up fine. Two things
didn't: a dropdown search that comes back with zero matches currently just goes quiet instead of
saying so, and a very long list can get a little too enthusiastic about redrawing itself while
you're still typing. Both are being fixed properly — tracked, not papered over. Smaller things
landed cleanly: the counter input's slide animation won't cut itself short on fast clicks anymore,
the two "copy" buttons in the AI components now share one brain instead of two, and we went hunting
for tangled wiring between files across the whole kit and came back with good news — none of it was
ever actually a problem, just old habits that looked worse than they were.

<Divider />

## v0.5.2 · Tue, Oct 20

Plumbing day. The connection between this kit and the AI assistant that reads it had quietly broken
weeks ago — pointed at a folder that didn't exist anymore — and nobody noticed because nobody had
needed it in a while. Fixed, and wrote down a rule so it can't happen the same way twice: one real
copy of this project per machine, not a drawer of forgotten clones. Also went through every `ref`
passed around the kit by hand, person by person, just to be sure each one lands where it says it
does.

<Divider />

## v0.5.1 · Mon, Oct 19

Back to the naming audit we'd been putting off. Sizes, booleans, callbacks, labels — every prop,
checked against every other component doing something similar, to make sure `small` means the same
thing twice and `isLoading` always behaves the way you'd bet it does. Found exactly one real
inconsistency worth fixing in the whole kit (a table prop that broke its own convention) and logged
it honestly for a proper rename later, since we don't rename things out from under people without
warning. Also brought Dropdown's open/close handler in line with the rest of its overlay family — it
was the one holdout speaking a different shape, which meant you couldn't share a handler between it
and, say, a date picker. Now you can.

<Divider />

## v0.5.0 · Fri, Oct 16

### Measure Twice, Ship Once

The kit had grown enough by now that small inconsistencies start sneaking in without anyone
deciding to let them — one component says `isOpen`, another says `open`; one spinner means
"loading," another means "disabled." So we stopped shipping new things for a stretch and just
checked. Every prop, every loading state, every timer, against every sibling that does something
similar. It's the least glamorous week we've had, and probably the most important one.

<Divider />

## v0.4.6 · Thu, Oct 15

A proper migration guide now ships with any breaking change, plus a small script that rewrites your
code for you when a prop gets renamed — find-and-replace, but it already knows what to look for.
Also added the first tests that open a real browser for the handful of things a snapshot genuinely
can't catch: a dropdown opening in the right spot, a drag gesture actually working.

<Divider />

## v0.4.5 · Tue, Oct 13

Table got a proper once-over. It's noticeably faster scrolling through a few thousand rows now — and
it finally does the grown-up things a table should: sort, filter, select across pages, edit a cell
without leaving the row you're on.

<Divider />

## v0.4.4 · Mon, Oct 12

An AI coding assistant is now plugged directly into the kit, so the right component and its docs
show up automatically while someone's building, instead of a tab-switch to go look it up. A Figma
plugin landed alongside it, so a design file can finally be checked against what's actually shipped
instead of a screenshot from three versions ago.

<Divider />

## v0.4.3 · Fri, Oct 9

Went through every input and button with a screen reader running, to make sure it hears what a
sighted person sees — not an approximation, the actual thing. Every bit of text in the kit is also
translation-ready now; shipping in another language is a configuration change, not a rewrite.

<Divider />

## v0.4.2 · Wed, Oct 7

Keyboard-only testing across every overlay — tab, escape, the arrow keys — until all of them behave
the way your hands expect and not just the way a mouse would. Visual regression screenshots are also
running automatically now: if a pixel moves without anyone asking it to, someone will see it before
it ships.

## v0.4.1 · Mon, Oct 5

Back from the long weekend. The kit now tracks its own weight automatically, and we went and

## v0.4.0 · Thu, Oct 1

### Built to Last

For the first month and a half, "it works" mostly meant "it worked when I checked it on my own
machine," which stops being good enough the moment more than one person is trusting it. This stretch
was about turning the kit into something a whole team could lean on without re-checking it
themselves first — automated style checks, automated size checks, real keyboard and screen-reader
testing, and the first outside tools that read the kit directly instead of through someone's notes.

<Divider />

## v0.3.0 · Wed, Sep 16

### The Human Touches

All the right pieces existed by this point, but pieces aren't the same as something that feels
considered. This stretch was about the details you only notice when they're missing — dark mode
done properly, motion that respects how a person actually wants to move through a screen, and a
whole new family of components for the thing everyone was suddenly building: chat interfaces for AI.
Dark mode shipped first, every color token flipping with it, nothing left glowing white in a dark
room because someone forgot a corner.

## v0.1.0 · Sat, Aug 15

### The Idea

A design system doesn't start with components, it starts with being tired of the same argument:
whose blue is the real blue, why does this button feel half a pixel off from that one, why does
"small" mean three different sizes depending who built it. The idea came together over a weekend,
which is usually how the honest ones do — no roadmap yet, no components, just a decision: one
shared language for color, type, and space, built to work the same way on web and mobile, that
everything else could stand on from here. Monday was for actually starting.
