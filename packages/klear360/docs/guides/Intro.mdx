## 📦 Packages

Klear360 has 3 packages

### [@klear/klear360](https://github.com/klear/klear360/tree/master/packages/klear360)

This package is under **active development**. We'll only refer to this version of klear360 throughout this documentation.

### [@klear/klear360-svelte](https://github.com/klear/klear360/tree/master/packages/klear360-svelte#readme)

This package brings Klear360 components to Svelte applications. It is currently under **active development** and new components are being added progressively.

### [@klear/klear360-old](https://github.com/klear/klear360-old#--klear360-old)

This package is under **maintenance** and it won't have any major releases. It will be **deprecated** once the newer version (`@klear/klear360`) is ready for a stable release. The repository is private and only accessible to Klear Employees. Documentation for this package can be found [here](https://github.com/klear/klear360-old#--klear360-old)

## 📝 Versioning & Publishing

* The first step in publishing a new version of klear360 is to first the mention the type of change and bump the version. We are using [`changesets`](https://github.com/atlassian/changesets) to handle automated versioning for us based on the intent of the change we mention in the PR.
* Once a PR is approved by the authors of klear360, based on if the PR needs a new version to be published the author will add a changeset to the PR.
* After the `changeset` is added and the PR is merged the `release` workflow gets triggered by GitHub actions.
* The `release` workflow runs `build` script which runs rollup to bundle `klear360` and generates relevant `types` as well.
* After the build script finishes, we'll have 3 bundles which will be published under `@klear/klear360` scope

```
@klear/klear360/components
@klear/klear360/tokens
@klear/klear360/utils
```

> 🗒 You can read in depth about our shipping strategy [here](https://github.com/klear/klear360/blob/master/rfcs/2021-06-15-shipping-klear360.md)
